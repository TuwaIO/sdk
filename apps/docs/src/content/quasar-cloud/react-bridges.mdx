# SIWX Authentication (Headless)

The `@tuwaio/sdk/siwx` module provides a headless, CAIP-122 compliant React hook `useSiwx` to handle multi-chain session authentication automatically on the frontend. 

## The Headless Approach

The modern TUWA stack separates the visual connection button (Nova UI) from the background authentication logic (SIWX). There are no "Bridge" UI components to render; you simply trigger sign-in flows after a wallet connects.

When a user connects their wallet (EVM or Solana), you can automatically prompt them to sign a CAIP-122 standard authentication message. Upon successful signature, a secure HTTP-Only cookie session is established with the backend API.

## Implementation

For a React application, the optimal way to auto-authenticate is by initializing your connection provider (`SatelliteConnectProvider`) with the `callbackAfterConnected` prop. This triggers the SIWX signature prompt immediately after the wallet is securely connected.

```tsx
// src/components/Providers.tsx
'use client';

import { ReactNode } from 'react';
import { SatelliteConnectProvider } from '@tuwaio/sdk/satellite';
import { useSiwx } from '@tuwaio/sdk/siwx';
import { isSafeApp, getAdapterFromConnectorType, OrbitAdapter } from '@tuwaio/orbit-core';
import { satelliteEVMAdapter } from '@tuwaio/satellite-evm';
import { satelliteSolanaAdapter } from '@tuwaio/satellite-solana';
import { wagmiConfig, appEVMChains, solanaRPCUrls } from '@/configs/appConfig';

export function Providers({ children }: { children: ReactNode }) {
  const { signIn } = useSiwx();

  return (
    <SatelliteConnectProvider
      adapter={[
        satelliteEVMAdapter(wagmiConfig, appEVMChains), 
        satelliteSolanaAdapter({ rpcUrls: solanaRPCUrls })
      ]}
      // Automatically request a SIWX signature after successful connection
      callbackAfterConnected={async (connector) => {
        const isEVM = getAdapterFromConnectorType(connector.connectorType) === OrbitAdapter.EVM;
        
        // Skip SIWX for Smart Contract wallets like Safe
        if (isEVM && isSafeApp) return;

        // Trigger sign-in flow
        await signIn();
      }}
    >
      {children}
    </SatelliteConnectProvider>
  );
}
```

### Behavior

1. **Connection**: The Satellite state machine establishes a new active wallet connection and fires the `callbackAfterConnected`.
2. **Signing Prompt**: The `signIn()` method evaluates the connected wallet and presents the user with a standard Web3 signature request following the strict CAIP-122 format.
3. **Verification**: The signature is automatically passed to your Quasar backend. Quasar validates the signature and issues an encrypted JWT session cookie.
4. **Session Active**: The local state is updated globally, and the user is fully authenticated to interact with restricted Quasar endpoints.

If the user disconnects their wallet, you can similarly invoke `signOut()` to invalidate the session.
